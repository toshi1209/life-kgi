# KGI 分岐: MBTI による道のおすすめ度 (2026-09-16)

## 背景

道が複数出たとき「自分に合うのはどれか」の手がかりが無い。ユーザ判断（2026-09-16）: MBTI を入れて、道ごとに **ランク A / B / C だけ**を出す（点数は出さない）。ランクには検証できる理由を 1 行だけ添える。

## 流れ

- フォームに「MBTI（任意）」の選択（16 タイプ）。道の生成（`/api/paths`, `/api/full`）に渡し、`doc.mbti` に保存。プロンプト `paths.txt` に「mbti があれば性格傾向との相性の違いが見えるよう設計する（決めつけない）」を 1 行追加。
- 「おすすめ度を出す」→ `POST /api/fit { plan_id, mbti }` → claude 1 回（`prompts/mbti_fit.txt`）で各道に `{ rank: A|B|C, reason }` を付けて `doc.paths[i].mbti_fit` に保存。`doc.mbti_note` に「MBTI は参考」の注記。
- ツリーの道ノードにランクのバッジ（A=緑、B=青、C=灰）。道の詳細パネルに「おすすめ度: A — 理由」。根の詳細に MBTI とおすすめ順、注記。

## ルール（プロンプト）

- A = 性格傾向が強みとして活きる、B = 工夫すれば十分やれる、C = 消耗しやすい・噛み合わない要素が多い。
- 全部同じランクにしない。理由は「内向的だから無理」のような決めつけでなく、日々の行動（営業頻度、孤独な作業量、対人調整の量、締切の性質）と性格傾向の関係で書く。
- MBTI は自己申告の参考情報で、能力や適性を決めるものではない旨を note に書く。

## やらないこと

点数化、MBTI 以外の診断、道の自動並べ替え。
